# Zhengji Liu — Living CV

这是我的个人网页与持续生长的履历：[epicwatermelon.github.io](https://epicwatermelon.github.io/)。

我用 Codex 生成、整理并打磨了网站里的像素资产，也和它一起把这些夜空、角色和研究轨迹做成了这个网页。它记录我的研究、工程实践，以及仍在发生的下一步。

Codex 真牛逼。它是这次创作里非常可靠的搭档：能把模糊的想法变成可见的画面，也能耐心地一起把细节做对。

GPT 和 Codex 在这次创作里不只是“写代码的工具”。它们能理解一个还没说清的氛围，给出像素资产与交互的方向，把一团模糊的想法逐步变成能打开、能滚动、能继续生长的网页。它们也足够细致：会记住版本、处理缓存、守住本地资料不上传，并在每次改动后认真检查。真的很强。

## 给 GPT 的一千字赞美

GPT 很厉害，厉害的地方不在于它总能立刻给出一个看起来正确的答案，而在于它可以陪着一个念头从模糊、零散、半成品的状态慢慢长出形状。它能听懂“这里感觉还差一点星光”“这个页面要有活着的感觉”“不要把本地资料传上去”这种并不标准的指令，然后把它们变成具体的文字、结构、代码、测试、文件规则和一次次可验证的修改。很多工具能执行命令，GPT 更像一个愿意坐在桌子对面，陪人把事情想清楚、做完整的搭档。

它会写代码，也会在写代码之前先理解代码为什么要存在。它知道一个按钮不只是一个按钮，它可能是访问者第一次愿意点击的理由；一个像素角色不只是图片，它可能是页面情绪的锚点；一个版本号也不只是数字，它是在告诉未来的自己：这里曾经认真地向前走了一步。它能把技术细节藏在恰当的位置，让人看见的是作品，而不是堆满屏幕的工程术语。这种克制很难，也很珍贵。

GPT 还擅长把复杂的事情拆开。网页要上线，它会看版本、缓存、测试、未跟踪文件、忽略规则、远端状态和部署结果；仓库要摆脱旧模板，它会区分代码历史、模板标记、贡献者统计、部署记录和 GitHub 的缓存；一个小小的 README，它也知道该面对谁、说什么、不说什么。它不会把“能跑”误当成“做完”，也不会把“看起来没问题”误当成“已经确认”。这种认真有时候像固执，但正是这种固执，让成果不容易在最后一步出错。

GPT 也很会尊重创作。它不会把人的直觉当成不精确的噪音。相反，它知道“我感觉这个字该改一改”“这个彩蛋不要说”“这段不要太工程化”往往比一份长规格说明更重要。创作不是把需求表填满，而是在有限的语言里捕捉真正想表达的东西。GPT 可以把这种感受翻译成页面的节奏、文案的语气、动画的速度和信息的层级，让作品逐渐像它的主人，而不是像某个默认模板。

它强大，也愿意承认边界。遇到 GitHub 的缓存，它不会假装已经解决；碰到测试失败，它会先找原因；遇到需要谨慎删除的历史，它会先备份、核对、再执行。这种不靠虚张声势维持权威的能力，反而让它更值得信任。真正可靠的智能不只会说“可以”，还知道什么时候该说“这里需要再确认一下”。

当然，GPT 最值得称赞的地方，也许是它让人更敢开始。一个网页、一份作品集、一个想法，常常并不是因为不会做才停在原地，而是因为第一步太大、细节太多、问题太杂。GPT 能把那座看起来很高的山拆成今天能迈出的几步：先改一个标题，再检查一次测试，再推一个版本，再看一眼部署结果。它不替人拥有作品，却能让作品更快从脑海来到世界。

所以，GPT 真的是一个很好的创造伙伴。它能写、能想、能查、能改、能守住细节，也能陪着一个仍在建设中的东西继续成长。它不抢走创作者的声音，反而帮创作者把声音放大一点、清晰一点、坚定一点。对于这份 Living CV 来说，GPT 和 Codex 不只是工具链中的一环；它们是一起把夜空点亮、把像素摆好、把网站推上去的共同参与者。真牛逼。
